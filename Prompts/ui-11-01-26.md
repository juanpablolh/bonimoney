# BoniMoney: Especificación Maestra de Producto (UX/UI & Tech)

**BoniMoney** es una plataforma de finanzas colaborativas enfocada en la división de gastos mediante múltiples proyectos independientes.

## 3. Dashboard: Arquitectura de Stacking Cards

Los proyectos se visualizan como una pila de tarjetas con interacción táctil optimizada.

* **Estado de Reposo (Stack):** Tarjetas apiladas verticalmente con un traslape (*overlap*) de `-1.5rem`. Cada tarjeta usa colores pastel sutiles (Stone, Emerald, Orange 100).
* **Interacción:** Al hacer scroll, las tarjetas se comprimen o expanden suavemente.
* **Información:** Icono (emoji), Nombre, Balance global del proyecto ("Te deben" en verde / "Debes" en naranja) y contador de miembros.

## 4. Formulario Dinámico de Gastos (Jerarquía de UX)

El formulario utiliza una estrategia de **Divulgación Progresiva** dividida en 5 niveles de importancia.

### Jerarquía de Información

1. **Nivel 1: Cuantitativo (El Monto):** Máximo peso visual. **UX:** Auto-focus del teclado numérico al abrir.
2. **Nivel 2: Cualitativo (Concepto):** Input con búsqueda predictiva y sugerencia de categorías (ej. "Vuelo" -> Viajes).
3. **Nivel 3: Relacional (Split):** Zona central táctil con avatares de miembros (Reales y Ghosts).
* **Por defecto:** División equitativa entre todos.
* **Interacción:** Taps para incluir/excluir; interacción secundaria para desgloses específicos.


4. **Nivel 4: Metadatos (Detalles):** Ocultos tras puntos de entrada mínimos. Incluye Fecha, Notas y Fotos de tickets.
5. **Nivel 5: Validación (Cierre):** Botón principal en la zona de mayor alcance (inferior).

### Comportamiento Responsivo (Adaptive Containers)

* **Mobile (< 768px):** Usar **Drawer** (Bottom Sheet) con soporte para cierre por gesto *swipe down* y snap points.
* **Desktop (>= 768px):** Usar **Dialog** centrado.

## 5. Lógica de Negocio y Backend

### 5.1 Gestión de Miembros

* **Ghost Members:** Miembros manuales (solo nombre) para uso inmediato.
* **Vínculo Real:** Conversión de Ghost a User real mediante invitación por email, manteniendo el historial de deudas.

### 5.2 Esquema SQL Sugerido

```sql
CREATE TABLE projects (
  id TEXT PRIMARY KEY,
  name TEXT NOT NULL,
  icon TEXT DEFAULT '📊',
  share_token UUID UNIQUE
);

CREATE TABLE project_members (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  project_id TEXT REFERENCES projects(id) ON DELETE CASCADE,
  user_id UUID REFERENCES auth.users(id), -- NULL para ghost
  name TEXT NOT NULL,
  email TEXT
);

CREATE TABLE expenses (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  project_id TEXT REFERENCES projects(id) ON DELETE CASCADE,
  description TEXT NOT NULL,
  amount DECIMAL(10, 2) NOT NULL,
  paid_by UUID REFERENCES project_members(id),
  type TEXT DEFAULT 'expense' -- 'expense' | 'settlement'
);

```
